# 多人协作标注建议

当前工作台默认是单机本地标注：每个人的修改会写入本机 `csv_data_annotated/annotation_state.json`，再导出 CSV。多人同时改同一个 CSV 时，最容易出现覆盖和冲突。

## 推荐方案 A：任务分片，最后合并

适合课程作业，最简单。

1. 按章节或一级知识点分工，例如：
   - A 同学：集合与映射、数列极限
   - B 同学：函数极限与连续、导数
   - C 同学：中值定理、积分
2. 每个人本地运行 UI，只标自己负责的章节。
3. 每个人导出自己的 `annotation_state.json` 或 `annotated_relationships.csv`。
4. 最后由一个人合并、去重、审核冲突。

优点：不用搭服务器，不依赖网络。  
缺点：需要最后集中合并。

## 推荐方案 B：共用一台标注服务器

适合你愿意租服务器或让一台电脑当局域网主机。

1. 在一台机器上运行 `python3 code/annotation_server.py`。
2. 把服务监听地址从 `127.0.0.1` 改成 `0.0.0.0`。
3. 小组成员访问同一个地址进行标注。
4. 所有数据写入同一份 `csv_data_annotated/annotation_state.json`。

优点：天然同步，不需要最后手工合并。  
缺点：需要处理网络访问、备份、并发写入和权限。

如果后续采用这个方案，建议增加：

- 标注人登录或至少固定填写 annotator
- 自动备份 `annotation_state.json`
- 保存时加文件锁
- 按章节筛选任务
- 冲突检测和操作日志

## 推荐方案 C：SQLite 后端

如果项目继续扩展，建议把 `annotation_state.json` 换成 SQLite。

优点：

- 多人写入更安全
- 方便查询、筛选和撤销
- 可以记录完整操作日志
- 最后仍然可以导出 Neo4j CSV

缺点：实现复杂度比当前 JSON 文件高一点。

## 当前最适合你们的选择

课程作业阶段建议用方案 A：

```text
按一级章节分片标注 -> 导出各自结果 -> 最后合并成一份增强关系 CSV
```

如果你们后面要做正式演示，再把它升级成方案 B 或 C。
